# 入门指南：家庭音乐服务器协议与共享组件

这份指南写给想“自己搭一个音乐服务器”、或者想“自己写一个兼容的服务器”的人。读完你会知道：这套东西是什么、怎么五分钟跑起来、要写一个自己的服务器需要做哪些事。

## 一、这是什么

我们定义了一套开放的“家庭音乐服务器协议”：服务器把音乐提供出来，播放器通过加密连接来浏览、搜索、播放。播放器只认协议，不关心服务器背后的音乐是从哪里来的——可以是你硬盘上的文件，也可以是别的什么，只要按协议回答就行。

这个仓库包含两部分：

| 部分 | 是什么 |
|---|---|
| **共享组件** | 协议的权威定义和可以直接复用的代码：数据结构、接口定义、加密连接、本地音乐扫描 |
| **轻量音乐服务器** | 用共享组件写成的一个最小服务器：一个菜单栏小程序，把电脑上的一个音乐文件夹提供给播放器。它既是可以直接用的服务器，也是“怎么写服务器”的完整示例 |

许可：代码全部 MIT；示例音乐、封面、歌词是本项目原创，CC0。没有使用任何第三方库，也不包含任何在线音乐平台的代码。

## 二、五分钟跑起来

需要一台 macOS 14 或更新的电脑。

1. 把“轻量音乐服务器.app”放进“应用程序”文件夹，双击打开。菜单栏右上角会出现一个小房子加音符的图标。
2. 点开菜单，选“放入示例音乐”。音乐文件夹里会多出三张原创示例专辑。
3. 记下菜单里的“地址、端口”和“账号、密码”。点一下这两行，就能拷贝。
4. 在支持本协议的播放器里“添加服务器”，填入地址、端口、用户名、密码。登录一次之后，播放器会拿到一把专属的设备密钥，以后就不用再输密码了。
5. 想放自己的歌：点“打开音乐文件夹”，把 FLAC、ALAC 或 AAC（m4a）、MP3、WAV、AIFF 拷进去，几秒后服务器就会认出来。同名的 .lrc 文件会当作歌词；专辑文件夹里的 cover.jpg，或者音频文件内嵌的封面，会当作封面。

菜单里还有“开机自动启动”。服务器只在你的局域网里提供服务，不需要也不建议把它暴露到公网。

## 三、仓库里的模块

| 模块 | 用途 | 要不要用 |
|---|---|---|
| `MusicCore` | 统一的数据结构：曲目、专辑、歌手、音质等 | 写服务器必用 |
| `MusicAPI` | 接口路径与请求、回复的数据结构（`API.Path`、各种 `…Response`） | 写服务器必用 |
| `SecureTransport` | 加密连接：TLS 1.2 预共享密钥，加一个最小的 HTTP；服务器端是 `SecureServer` | 用 Swift 写服务器时直接用 |
| `ProviderKit` | “来源”的协议（搜索、资料库、详情、歌词、取音频等能力），以及歌词解析、音频格式解码 | 按需 |
| `LocalMusic` | 扫描本地音乐文件夹：读标签、封面、整轨分轨，把一个文件夹变成一个完整的“来源” | 想提供本地音乐时直接用 |

协议的完整说明见 `docs/protocol.md`；权威定义以源码为准。

## 四、自己写一个服务器：最少要做什么

### 1. 加密连接

- 一个 TCP 端口，只接受 TLS 1.2 预共享密钥连接，密码套件固定为 `TLS_ECDHE_PSK_WITH_CHACHA20_POLY1305_SHA256`（编号 0xCCAC），不启用会话复用。
- 身份和密钥：
  - 第一次登录用身份 `u:<小写用户名>`。密钥由密码派生：PBKDF2-HMAC-SHA256，盐为 `AccessibleMusic/v1/user/<小写用户名>`，60 万次，32 字节。服务器只保存派生出来的密钥，不保存密码。
  - 登录成功后，服务器发给这台设备一把 32 字节的随机设备密钥；之后都用身份 `d:<设备编号>` 加这把密钥连接。
- 每个连接一个请求，使用最小的 HTTP/1.1。

用 Swift 的话，这些都由 `SecureServer` 和 `TransportSecurity` 做好了，你只需要写“收到请求怎么回答”：

```swift
import SecureTransport
import MusicAPI

let user = TransportSecurity.passwordEntry(username: "demo", password: "你的密码")
let server = SecureServer(port: 7710) { peer, request in
    // peer 里有对方的身份（u:… 或 d:…），request 里有方法、路径、查询参数、请求体
    switch request.path {
    case API.Path.server:
        // 回复服务器版本、协议版本和声明的功能
        return .json(200, /* JSON 编码后的回复 */ Data())
    default:
        return .status(404)
    }
}
try await server.start(keys: [user /*, 已登录设备的密钥 */])
```

用别的语言写也可以，只要你的 TLS 库支持预共享密钥和上面那个密码套件。

### 2. 必须实现的接口

| 接口 | 作用 |
|---|---|
| `POST /v1/session/login` | 用密码身份登录，换取设备编号和设备密钥 |
| `GET /v1/server` | 服务器版本、协议版本（目前为 2）、声明的功能 |
| `GET /v1/providers` | 来源列表：每个来源的名称、能力、音质级别。**播放器完全按这里显示功能** |
| `GET /v1/me` | 当前用户和各来源的账户状态 |

一个只提供本地音乐的最简服务器，再实现这几个就能浏览和播放了：`search`（搜索）、`library`（资料库）、`track`（曲目详情）、`lyrics`（歌词）、`stream/open`（打开音频）、`stream/{编号}`（按字节范围读取音频，必须支持 `Range`，回 206 和 `Content-Range`）。专辑、歌手的曲目，封面等接口见 `API.Path`。

轻量音乐服务器的 `LightServer/Sources/LightServerCore/Router.swift` 就是这些接口的完整实现，照着读最直观。

### 3. 来源编号就是“槽位号”

- 服务器上的每个来源（比如“本地音乐”）都有一个编号，是十进制数字字符串 `"1"`、`"2"`……
- 号一旦分配就永久不变，来源去掉了也不回收。播放器按这个号记住你在这个来源上的偏好，比如音质。
- 显示顺序看来源列表的先后，和号的大小无关；名称、能力可以随时改。
- 轻量音乐服务器只有一个来源“本地音乐”，用 1 号。

### 4. 通用音质档位

各来源的音质名称五花八门。服务器可以给每个音质标上通用档位：1 省流、2 标准、3 高品质、4 无损、5 高解析、6 高解析 96、7 高解析 192、8 DSD。另外还可以标注是否多声道、是否空间音频。这些都是可选的；播放器靠它统一显示，并按用户设的上限挑“不超过上限的最高一档”。按文件实际格式归档的规则，见共享组件的 `QualityTier.classify`。

### 5. 出错时怎么回

非 2xx 的回复，内容为 `{"category": "<错误类别>", "message": "<给用户看的话>"}`。播放器会直接把 `message` 显示给用户。不支持的功能，就回 501 加一句说明，播放器不会卡住。

### 6. 只声明你真正做到的

播放器只显示服务器在 `/v1/server` 和 `/v1/providers` 里声明了的功能。做不到的就不要声明——宁可少，不要假。

## 五、编译与测试

需要 Xcode（Swift 6）；轻量服务器的菜单栏应用工程用 XcodeGen 生成。

```sh
# 共享组件（在仓库根目录）
swift build && swift test

# 轻量服务器
cd LightServer
swift test
scripts/编译安装.sh                               # 编译并装到“应用程序”
swift run lms-check 127.0.0.1 7710 demo <密码>    # 连接测试：登录、列专辑、取封面、完整读一首歌
```

## 六、原则

- 协议按“能力”设计，不为某个平台单独开特例：新来源只要实现能力，播放器不用改。
- 结构上留足扩展余地；不认识的字段、类型、档位，播放器都会安全地忽略或照常显示。
- 这里不包含、也不接受任何在线音乐平台的代码。
